Fallback story — for the judges

say this

Primary: live scraping of 5 airline / OTA portals — real headless browsers that intercept each site's own fare XHR. Everything is live — that is what makes us different.

Tier 1 fallback: a source is blocked → the Travelpayouts (Aviasales) data API supplies that route's fares.

Tier 2 fallback: fully offline → the last cached scrape snapshot.

Every run reports which tier was used (ingestion_source). DGCA volume weights are never scraped — that is an official statistic.

what changed from earlier drafts

Self-healing vision-LLM extractor (1.5c) — removed, replaced by a CSS-selector fallback.

Free LLM API key — removed. No external AI APIs anywhere.

Explainability LLM — removed, replaced by a rule-based template annotator.

pywebview desktop shell — skipped; the browser console is the shell (note: PS says "desktop app", so keep pywebview as a ~15-line stretch goal if time allows).

Build order (do not skip ahead)

Engineering deep-dive §10. Tell the tool: "only build stage N, don't implement later stages."

  • 1 Scaffold — folders, stub functions with correct signatures, requirements.txt, .env.example, config.py
  • 2 Cache-seeded fallback — seed data/cache/ from Kaggle, fetch_fares returns it
  • 3 SSE bridge — real run_audit generator, hardcoded lines, wired to EventSource
  • 4 Festival engine → 5 IQR filter → 6 Laspeyres (each with its golden-number test)
  • 7 Live scraper pool — one adapter, then cache layer, then Travelpayouts fallback, then fan-out to all 5
  • 8 Persistence — Postgres (Docker) + SQLite fallback + schema.sql
  • 9 AI models — train integrity + nowcast offline, wire inference as pure functions
  • 10 Explainability annotator + polish — /api/runs, CSV import, PDF report data
