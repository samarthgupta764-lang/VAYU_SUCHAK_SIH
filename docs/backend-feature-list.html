Backend Feature List — Complete

Every backend feature to build for VAYU-SUCHAK 2.0, including the self-trained AI models. Architecture is live-first: real headless-browser scraping of airline and OTA portals is the primary path and the core differentiator. Travelpayouts (Aviasales) data API is a formal fallback tier; an on-disk cache snapshot is the last resort. No external AI APIs — all models are trained in-house on free datasets.

Live Acquisition — the differentiator

Real headless browsers scrape 5 airline / OTA portals live. Everything is live — that is what sets the project apart. When a source is blocked, the Travelpayouts data API fills that route; only when fully offline does the on-disk cache serve.

1B  Fallback Chain — 3-tier resilience

#FeatureDetail
1.15Tier 1 — Travelpayouts API fallbacklive scrape fails / blocked → api.travelpayouts.com (Aviasales data: prices_for_dates / cheapest fares) for that route, mapped into the same normalise contract. Token in .env.
1.16Travelpayouts clienthttpx.AsyncClient, auth header, response → list[dict] in record shape, currency normalised to INR
1.17Tier 2 — on-disk cache snapshotTravelpayouts also unreachable (offline) → newest cached JSON for source_corridor_date
1.18Cache writerevery successful scrape / API response written to disk, timestamped, data/cache/
1.19Cache seed scriptKaggle dataset → 30–50 rows/corridor as initial cache (record shape) so the pipeline runs on day one
1.20Fallback taggingeach record + run tagged ingestion_source = live_scrape / travelpayouts / cache, console emits [SCRAPE][FALLBACK]
1.21Graceful degradation1 source blocked → other 4 + Travelpayouts still contribute; run completes, sources_degraded count reported

Dynamic IQR Purifier — pipeline/iqr.py

#FeatureDetail
3.1Two-tailed Tukey fenceQ1 − k·IQR and Q3 + k·IQR — catches both glitch-low (₹1, null-as-0) and absurd-high
3.2clean[] / anomalies[] splitdriven by k_factor; price within fence → clean, else anomaly
3.3Exclusion metadataeach anomaly gets exclusion_reason (below_lower_fence / above_upper_fence) + the fence value
3.4Fences object returned{Q1, Q3, IQR, lower_fence, upper_fence} → feeds histogram + console
3.5Nothing deletedanomalies logged + stored + returned — any k choice is reversible
3.6Golden-number testtest_iqr.py — worked example: k=1.5 → 2 excluded, k=3.0 → 1

05

AI · Nowcasting / Imputation Model — pipeline/ml/nowcast.py

Fills route-days a live scrape missed — imputation, not forecasting. This is how central banks nowcast GDP.

#FeatureDetail
5.1Gradient-boosted regressorlightgbm / sklearn.GradientBoostingRegressor — fills sparse route-days (a route-day whose scrape failed)
5.2Featurescorrelated routes' current prices, route history, day-of-week, days-to-departure, festival flag, fuel-price proxy
5.3Confidence bandsquantile regression (10th / 90th) or bootstrap → an interval on every imputed value
5.4NOT forecastingonly imputes missing observed route-days — never predicts future prices. Explicit in console + docs.
5.5Self-training pipeline (train_nowcast.py)Kaggle + accumulated scrape data, no API
5.6Model artifact + versioningmodels/nowcast_v1.joblib + metrics (MAE, CI coverage)
5.7Inference as pure functionimpute_gaps(route_day_matrix) → (complete_matrix, imputed_mask, confidence_bands)
5.8Imputation flag on outputrun reports imputed_route_days count; index carries a confidence band to the frontend

Weighted Laspeyres Engine — pipeline/laspeyres.py

#FeatureDetail
6.1Per-route aggregationpandas groupby("route")["price"].median() (median = outlier-robust) → Pt
6.2Base-year joinbase_year_reference.json → P0, Q0 per route, inner join (routes present in both)
6.3Laspeyres formulaIndex = Σ(Pt·Q0) / Σ(P0·Q0) × 100
6.4Festival decompositionindex_all vs index_ex_festival (re-run on non-flagged fares only) → festival component in index points
6.5Per-route table returnedPt, P0, Q0, pt_q0, p0_q0 inspectable table → PDF report + readout
6.6Vectorised, deterministicno loops, no random seeds — same input = same output
6.7Golden-number testtest_laspeyres.py — 2-route example = exactly 118.75

Fallback story — for the judges

say this

Primary: live scraping of 5 airline / OTA portals — real headless browsers that intercept each site's own fare XHR. Everything is live — that is what makes us different.

Tier 1 fallback: a source is blocked → the Travelpayouts (Aviasales) data API supplies that route's fares.

Tier 2 fallback: fully offline → the last cached scrape snapshot.

Every run reports which tier was used (ingestion_source). DGCA volume weights are never scraped — that is an official statistic.

what changed from earlier drafts

Self-healing vision-LLM extractor (1.5c) — removed, replaced by a CSS-selector fallback.

Free LLM API key — removed. No external AI APIs anywhere.

Explainability LLM — removed, replaced by a rule-based template annotator.

pywebview desktop shell — skipped; the browser console is the shell (note: PS says "desktop app", so keep pywebview as a ~15-line stretch goal if time allows).

Build order (do not skip ahead)

Engineering deep-dive §10. Tell the tool: "only build stage N, don't implement later stages."

  • 1 Scaffold — folders, stub functions with correct signatures, requirements.txt, .env.example, config.py
  • 2 Cache-seeded fallback — seed data/cache/ from Kaggle, fetch_fares returns it
  • 3 SSE bridge — real run_audit generator, hardcoded lines, wired to EventSource
  • 4 Festival engine → 5 IQR filter → 6 Laspeyres (each with its golden-number test)
  • 7 Live scraper pool — one adapter, then cache layer, then Travelpayouts fallback, then fan-out to all 5
  • 8 Persistence — Postgres (Docker) + SQLite fallback + schema.sql
  • 9 AI models — train integrity + nowcast offline, wire inference as pure functions
  • 10 Explainability annotator + polish — /api/runs, CSV import, PDF report data
